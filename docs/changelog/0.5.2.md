## [0.5.2] - 2026-09-22

### Added

- **An ingest route for training loops** (ADR-0063). `vernier.adapters`
  gains `coco_inputs`, `coco_inputs_from_columns`, `coco_metrics` and
  `gt_image_sizes`, plus the `Prediction` / `Target` /
  `DetectionColumns` / `TargetColumns` shapes they read. A trainer gets
  vernier's evaluation inputs in one call, instead of the ~250 lines of
  conversion each integration has had to write for itself.

  Two spellings of one conversion: `coco_inputs` for per-image records,
  `coco_inputs_from_columns` for state that is already concatenated —
  which is what a TorchMetrics-shaped metric holds, and where splitting
  it into records only to concatenate it again is the most expensive
  thing on the path. Both land on one builder, pinned to the identical
  `dataset_hash`, so they cannot drift.

  Both return the `(CocoDataset, DetectionsInput)` pair rather than a
  metric, so `Evaluator`, every `evaluate_*_grid` / `evaluate_*_summary`
  entry point, custom grids (ADR-0040), calibration through
  `cells_from_grid` and the partitioned/DDP path all compose with it;
  `coco_metrics` is the convenience wrapper for the AP case. TIDE, LRP,
  the confusion matrix and the `tables=` path still ask for GT JSON
  bytes — a pre-existing `CocoDataset` limitation of those surfaces, not
  of this route.
  `gt_image_sizes` is the columnar mirror of the already-published
  `detection_image_sizes`, which ADR-0055 had left to the caller.

  **Neither builder takes an `iou_type`** — the masks decide. Records
  carrying them produce inputs a `segm` grid can read, records without
  produce bbox-only inputs, and the IoU type is named once, at the grid
  or at `coco_metrics`. One set of inputs therefore serves every pass of
  a multi-IoU-type run. `boxes` are correspondingly optional whenever
  masks are present, where no kernel reads them; `coco_metrics` refuses
  `iou_type="bbox"` in that case rather than scoring the zero column.

  Arrays are read through DLPack or `numpy.asarray`, and a device
  tensor is moved by duck-typed `.detach()` / `.cpu()`. **No new
  dependency, and no vernier module imports a framework** — ADR-0031's
  "no torch dependency, ever" is now a CI gate
  (`tests/python/test_no_framework_imports.py`) rather than prose.

  The route encodes the rules an integration otherwise rediscovers,
  most of which are silent when violated: an `images` entry for every
  image including annotation-less ones; annotation ids from 1; a
  per-element `area` fallback that reads the mask whenever the
  annotation carries one, under either IoU type, because that is what
  `COCOeval` buckets by; `iscrowd` widened to `int64`; mask-derived
  image sizes; and the `(1, 0)` empty-box shape TorchMetrics produces.

  Verified bit-equal at `float32` to
  `MeanAveragePrecision(backend="pycocotools")` on bbox across all three
  box formats, on segm, and across a two-IoU-type run, and to its
  per-class loop for `map_per_class` / `mar_100_per_class`.
  `CocoDataset.dataset_hash` pins the ground truth as byte-identical to
  the COCO-JSON route built from the same records.

  Measured against a hand-rolled conversion in a real trainer
  (median of 21, four cores pinned, all metrics identical): **-9.9%**
  on a 1000x300 bbox run, **-2.1%** on a val-shaped 5000x300 / 80-class
  run, **-3.3%** with segmentation — while removing 209 lines of
  integration code and adding 57.

### Changed

- ADR-0055 moves from `proposed` to `accepted`; it shipped in `fb8f4b9`
  and ADR-0063 cites it as settled.

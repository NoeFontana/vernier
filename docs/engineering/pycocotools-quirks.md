# pycocotools quirks survey

A working note (not an ADR) cataloguing the numerical and structural quirks of `pycocotools` 2.0.11 that vernier must reckon with. (Survey originally written against 2.0.8; 2.0.11 adds NumPy 2.0 compatibility and one extra line in `loadRes` that preserves the `info` field. No algorithm changes.) Each row is a quirk we discovered by reading the source line-by-line; ADR-0002 disposes of every row as one of:

- **strict** — vernier's user-facing output matches pycocotools bit-for-bit. The implementation may be structurally different where that gives cleaner / faster code; row rationale notes when this is the case.
- **corrected** — vernier opts to fix this. Default behavior diverges from pycocotools and the divergence is documented as an opinionated improvement; `parity_mode="strict"` reproduces the original.

(The original three-tier model included a third disposition, `aligned`, for "semantic match with cleaner implementation". ADR-0002 was [amended on 2026-05-10](../adr/0002-three-tier-parity-model.md#amendment-2026-05-10-collapse-aligned-into-strict) to fold that tier into `strict` — every row previously tagged `aligned` was already asserted bit-equal in tests, so the third tier was a review-time annotation, not a tolerance budget.)

The disposition column below is ratified by ADR-0002.

Conventions used below:
- "ce" = `cocoeval.py`, "co" = `coco.py`, "mp" = `_mask.pyx`, "mc" = `maskApi.c`.
- Line citations like `ce:276` mean `cocoeval.py:276`. They point into the
  *pinned* `pycocotools-2.0.11` sdist, which never moves, so they are safe.

## Citing vernier's own code (the `Wired-by` column)

The `Wired-by` column cites **names, never line numbers**:

    `<path>::<name>`

`<name>` is a definition that exists in `<path>` — a function, test,
struct, enum, trait, const or method. vernier's own files move on
every refactor, so a `file:line` citation is stale the moment someone
inserts a line above it, and nothing reads it back. Names change only
when a human renames or deletes the thing, which is exactly when the
citation should be revisited.

`<path>` may be abbreviated against either root below; lengthen it when
the short form is ambiguous (`dataset.rs`, `parity.rs` and
`summarize.rs` all exist in more than one crate). Where the cited item
is a long function, the row also names the inline marker comment to
look for (e.g. `` `// B3:` ``).

## C. Recall integration and PR curve

| # | Quirk | Source | Disposition | Wired-by |
|---|---|---|---|---|
| C1 | 101-point recall integration: `recThrs = linspace(0, 1, 101)`. AP is the mean of interpolated precision at exactly these 101 recalls. Uses `np.searchsorted(rc, recThrs, side='left')` to find the first cumulative recall `>= rt`. | ce:507, ce:402 | **strict**. | C2 | Precision envelope: descending sweep `for i in range(nd-1, 0, -1): if pr[i] > pr[i-1]: pr[i-1] = pr[i]`. | C3 | If a recall threshold is unreachable (`searchsorted` returns `nd`), the bare `try/except: pass` swallows the resulting IndexError and leaves remaining `q[ri]`/`ss[ri]` at zero. Means precision at unreached recalls is exactly **0**, not -1. | ce:402-408 | **strict** but **rewrite without `except:`**. | C4 | `recall[t,k,a,m] = rc[-1] if nd else 0` — "AR" is the **terminal** cumulative recall (i.e., total TPs / total positives), *not* the area under a PR curve's recall axis. Document loudly. | `accumulate.rs::accumulate_cell` (`// C4:`); test `accumulate.rs::perfect_match_yields_ap_one_and_ar_one`. ✓ |
| C5 | Absent-category sentinel: `precision`, `recall`, `scores` arrays initialized to `-1`. `summarize()` filters with `s[s>-1]` before computing the mean. Cells with `npig > 0` but no detections (`n_d == 0`) still reach the assignment and land at `0.0`, because the inner `try/except` over an empty `pr` bails on the first index and `q` is written verbatim (this overlap with quirk **C3** is by design). | ce:334-336, ce:452-455 | **strict**. | `accumulate.rs::accumulate` (sentinel init) + `accumulate.rs::accumulate_cell` (`n_d == 0` zero-fill), `vernier-core/src/summarize.rs::mean_slice` (`v > -1.0` filter); tests `accumulate.rs::cell_with_only_ignore_gts_skips_entirely`, `accumulate.rs::no_dt_with_real_gt_yields_zero_recall_and_zero_precision`. ✓ |
| C6 | `pr.tolist()` and `q.tolist()` then iterate as Python lists for the inner monotonic sweep — explicit comment "numpy is slow without cython optimization for accessing elements". A vector op (`np.maximum.accumulate(pr[::-1])[::-1]`) gives the same result much faster. | ce:396 | **strict**. Vernier needs no `.tolist()`: the sweep is a scalar right-to-left loop directly over `Vec<f64>` — the *same* operation as **C2**'s precision envelope — so it is trivially bit-equal to pycocotools' list-iterated form. | `accumulate.rs::accumulate_cell` (`// C2:`, shared with **C2**); covered by `accumulate.rs::precision_envelope_runs_right_to_left` and `accumulate.rs::vectorized_inner_sweep_matches_naive_reference`. ✓ |
| C7 | TP/FP are computed as `logical_and(dtm, logical_not(dtIg))` and `logical_and(logical_not(dtm), logical_not(dtIg))`. A DT that matched an ignore-GT is in *neither* set. | ce:375-376 | **strict**. | `accumulate.rs::accumulate_cell` (`// C7:`); test `accumulate.rs::ignored_dt_does_not_count_as_fp`. ✓ |
| C8 | `np.spacing(1)` ≈ 2.22e-16 used as eps in `pr = tp / (fp+tp+np.spacing(1))`. Per-platform/numpy-version reproducible but *not* a clean constant. | ce:385 | **strict**. eps pinned to `f64::EPSILON`, bit-equal to `np.spacing(1)` on every supported platform. | `vernier-core/src/parity.rs::PARITY_EPS`; test `vernier-core/src/parity.rs::parity_eps_matches_numpy_spacing_1`. ✓ |

| F7 | The OKS mean is a true division: `np.sum(np.exp(-e)) / e.shape[0]`. Hoisting a `1.0 / count` reciprocal out of the DT loop and multiplying is **not** bit-equal: for any `count` that is not a power of two the reciprocal rounds once and the product rounds again, versus one correctly-rounded divide. Measured over uniformly random term-sums: 8.4% of cells differ by 1 ULP at `count == 17`, 29.4% at 14, 36.6% at 133 (0% at 16, 32, 64 — exact reciprocals). A 1-ULP shift is not cosmetic, because the matching ladder gates on `iou >= t` (**B2**): with 35 keypoints, 28 of them matched exactly and 7 underflowing `exp(-e)` to `0.0`, `28.0 / 35.0` is exactly `0.80` (matches at the ladder's 7th threshold) while `28.0 * (1.0 / 35.0)` is `0.7999999999999999` (does not). ## Glossary cross-reference

Cheat-sheet for the ratified dispositions (post-2026-05-10 amendment):

- **Most quirks: strict.** pycocotools is the reference; reproducing observable behavior is the parity claim. Implementations may differ structurally where that gives cleaner / faster code, as long as outputs are bit-equal — see the rationale on each row.
- **A handful of corrected:** A3 (flat-index re-accumulate), C3 (bare except), D1 (overwritten ignore field), H2 (silent merge), I2 (-1 sentinel), I6 (1-D reshape bug), J6 (heterogeneous DT dispatch), K1 (2-point polygon collision), L3/L5/L6/L7 (API hygiene), L9 (aggregate AP at a ladder without 100), F1 (per-category sigmas), F6 (keypoints under `useCats=0`).

Each `corrected` item is a behavior change that is opt-in (`parity_mode="strict"` reproduces the original) or documented as an intentional break.

- **One scoping note (I7).** "Bit-equal to pycocotools" means bit-equal to `pycocotools==2.0.11` *as published on PyPI* — the artifact `pyproject.toml` pins and the parity harness installs. A pycocotools the user rebuilds from the sdist with a contracting compiler is a different reference; on aarch64 it may land 1–2 ULP from vernier on bbox IoU. See [ADR-0056](../adr/0056-pin-no-fp-contraction-for-bbox-iou.md).

## Resolved questions

These five readings were once uncertain and flagged for a reproducer. All are now
resolved — each was answered with the fixture/test cited in its disposition row above:

1. **B1 + integer IoU** — `min(t, 1-1e-10)` does allow IoU=t to match for `t<1`; the `t=1`
   edge is covered. Resolved by fixture `iou_at_threshold` + tests
   `b1_iou_exactly_at_threshold_matches`, `b1_iou_at_one_still_matches` (row B1).
2. **D6 vs D7** — the eval-time `_ignore` filter uses non-strict inclusion (a boundary-area GT
   lands in both adjacent buckets); `getAnnIds(areaRng=...)` is out of scope (no such API).
   Resolved by fixture `boundary_area_segm` (row D6).
3. **H3** — polygon traversal direction does perturb thin-edge pixels. Resolved by fixture
   `self_intersecting_polygon_segm` (row H3).
4. **K1 (2-point polygon)** — vernier rejects ambiguous polygon/bbox input rather than guessing.
   Resolved by `polygon.rs::rejects_odd_coordinate_count` and siblings (row K1).
5. **G3 sign extension** — the Rust two's-complement port agrees on big counts. Resolved by
   `codec.rs::negative_differential_uses_sign_extension` (row G3).

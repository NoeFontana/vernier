# v0.0.1 vernier-bench baseline snapshot — pre-optimization

The pre-Stage-2 measurement baseline across all four paradigms. Stage 1 of
ADR-0033 landed the harness extension + cells; this doc captures
"where we started from" before per-paradigm optimization (rayon / pulp
work) lands, so the deltas can be read against a stable reference.

This is a **structural** snapshot. Numbers under each cell are
placeholders until the bench cells are run on a deterministic machine
in release mode (`vernier-bench run --mode release`); see §Run
instructions for the exact commands. The 2026-05 detection-only
snapshot at [`2026-05-snapshot.md`](2026-05-snapshot.md) is the prior
art for the per-cell tables we'll populate here.

## Shared configuration

- **Harness mode**: release (N=10 measurement reps + 2 warmup,
  randomised impl order per rep, IQR-relative-to-median gate at 5%)
  for the headline tables; dev mode (N=1) is fine for cell-existence
  smoke.
- **Result-store path**: paradigm-segmented per ADR-0033 §"Result-store
  path scheme v2": `bench/results/<sha>/<fp>/<paradigm>/<workload>/<metric>/<impl>.{json,npy}`.
- **Parity tiers** (per cell, ADR-0002 + per-paradigm extensions):

  | paradigm   | tier(s)                                          | oracle                                  |
  | ---------- | ------------------------------------------------ | --------------------------------------- |
  | instance   | strict (vs pycocotools) + aligned (vs fce) + boundary (vs boundary-iou-api) | pycocotools / faster-coco-eval / boundary-iou-api |
  | panoptic   | strict vs `pq_compute_single_core(proc_id=0)`    | panopticapi @ pinned SHA                |
  | semantic   | aligned (S3-B) — derived float metrics within rtol | mmsegmentation `IoUMetric` (ADE20K)   |
  | streaming  | strict — `Summary.stats` bit-equal batch↔stream  | (no external oracle; algebraic)         |
  | streaming/p99 | informational — no parity, regression-only   | (none — tail latency)                   |

- **Pinned baseline versions** — see `bench/envs/*/pyproject.toml`
  + `crates/vernier-{panoptic,semantic}/src/parity.rs` constants.
  Bumping any of these is an ADR-level decision (the parity contract
  follows the pin).

## Run instructions — capturing the baseline

The following commands populate the per-cell results under
`bench/results/<sha>/<fp>/...`. Run them on a quiescent machine
(release mode kicks the cpufreq governor pre-flight if exposed).

```bash
# Instance — bbox/segm/boundary on val2017 jittered (load-bearing
# detection cell).
just bench-sync-detection-envs   # equivalent to: uv sync per env
vernier-bench run --paradigm instance --workload coco_val2017_jittered_seed0 --iou bbox  --mode release
vernier-bench run --paradigm instance --workload coco_val2017_jittered_seed0 --iou segm  --mode release
vernier-bench run --paradigm instance --workload coco_val2017_jittered_seed0 --iou boundary --mode release

# Instance — keypoints, LVIS (LVIS gated by VERNIER_BENCH_DOWNLOAD_TESTS=1).
vernier-bench run --paradigm instance --workload coco_val2017_keypoints_jittered_seed0 --iou keypoints --mode release
VERNIER_BENCH_DOWNLOAD_TESTS=1 vernier-bench run --paradigm instance --workload lvis_v1_val_perfect --iou bbox --mode release
VERNIER_BENCH_DOWNLOAD_TESTS=1 vernier-bench run --paradigm instance --workload lvis_v1_val_perfect --iou segm --mode release

# Panoptic — perfect-match smoke (sub-minute).
uv sync --directory bench/envs/panopticapi
vernier-bench run --paradigm panoptic --workload coco_panoptic_val2017_perfect --mode release

# Semantic — first MVB cell deferred to S3-B (ADE20K + mmseg).

# Streaming — three coupled cells.
vernier-bench run --paradigm streaming --workload coco_val2017_streaming_throughput  --mode release
vernier-bench run --paradigm streaming --workload coco_val2017_streaming_vs_naive    --mode release
vernier-bench run --paradigm streaming --workload coco_val2017_dlpack_vs_json        --mode release

# BackgroundEvaluator p99 — informational; --duration-s defaults to
# 60s × 3 queue depths so this cell is ~3 minutes per impl.
vernier-bench run --paradigm streaming --workload coco_val2017_bg_saturation        --mode release --no-parity
```

## Optimization targets — what each paradigm's Stage 2 work reads against

Per the rayon-ADR pattern, each B-cell sets the optimization target;
optimization PRs read `compare --base <prior_sha> --head <new_sha>`
against the cell.

| paradigm   | optimization target cell                  | candidate lever                                                  |
| ---------- | ----------------------------------------- | ---------------------------------------------------------------- |
| instance   | `coco_val2017_jittered_seed0` × {bbox, segm, boundary} | rayon for the AP fold, pulp for IoU kernels, RLE accumulate     |
| panoptic   | `coco_panoptic_val2017_perfect`           | PNG decode hot path (the `png` crate vs panopticapi's Pillow loop) |
| semantic   | `ade20k_val_perfect` (S3-B)               | pulp `Arch::dispatch` on the per-pixel `gt * n_classes + pred` reduction |
| streaming  | `coco_val2017_streaming_vs_naive`, `coco_val2017_dlpack_vs_json` | DLPack tax close-out (ADR-0030), per-image accumulator amortisation |
| streaming  | `coco_val2017_bg_saturation`              | tail-latency reductions in the worker queue path (lock contention, scheduling) |

## Provenance

- **ADRs**: 0017 (bench harness foundation), 0033 (multi-paradigm extension),
  0014 (BackgroundEvaluator), 0025 (panoptic), 0028 (semantic), 0030 (DLPack ingest).
- **Pinned oracle versions**:
  - pycocotools `2.0.11` (the parity oracle; bumping is an ADR-level decision)
  - panopticapi at the SHA in `crates/vernier-panoptic/src/parity.rs::ORACLE_COMMIT_SHA`
  - Pillow `12.2.0` (panopticapi env)
- **Schema**: bench-result schema v2 (paradigm-segmented). Migration tool
  for v1 result trees: `vernier-bench migrate v1-to-v2`.
- **Reservations against Stage 3**: real-prediction caches stub URLs/SHAs in
  `tools/real_predictions_cache/{__init__,panoptic,semantic}.py` — populating
  them is an additive change with no code-path impact.

## Known gaps at v0.0.1

These are explicitly deferred to follow-up work; they belong in the
v1.0 polished snapshot, not here.

- **Real-prediction cells**: Mask R-CNN / rf-detr / Mask2Former / OCRNet
  blobs unhosted. Cache adapters in place.
- **Cityscapes dropped**: the original Stage 1 plan included a
  Cityscapes B2 cell as the semantic MVB. It was dropped because
  Cityscapes' [license](https://www.cityscapes-dataset.com/license/)
  restricts redistribution of derivative outputs in a way that
  doesn't fit a public bench-result tree. The semantic paradigm's
  first concrete cell now lands at S3-B (ADE20K + mmseg). The library
  preset `vernier.semantic.Dataset.cityscapes(...)` remains valid for
  users running on their own Cityscapes installs — only the bench
  cell is gone.
- **ADE20K + mmseg**: env not added (deferred to S3-B; ~5–8 min `uv sync`).
- **Boundary-PQ** (ADR-0025 Z1): pending upstream fork resolution.
- **Cross-machine aggregation**: ADR-0017 deferral kept; results scoped per machine.

## How to refresh this snapshot

After running the cells in §"Run instructions", pull the per-cell numbers from
`bench/results/<sha>/<fp>/<paradigm>/<workload>/<metric>/<impl>.json` (the
`aggregation` block has the median + IQR + RSS) and replace the `<TBD>`s. The
machine fingerprint at the top + git_sha + run-time should be recorded once at
the bottom of this file in a "captured on" footnote so the snapshot is
reproducible.

# 2026-10 release round — the 0.5.5 numbers

Full release-mode re-measurement ahead of tagging `v0.5.5`, at
`c30db82867de` on host `a6ada888c850`. Every published cell comes from
this one result tree, including the real RF-DETR cells, which the
renderer now picks up directly instead of having them hand-mirrored
from a separate snapshot.

**The host is the same VPS as the 0.4.0 round, but has a new fingerprint.**
CPU model, core count (8 logical) and RAM (32 GiB) are unchanged. The
fingerprint moved because the kernel release in its hash input is now
`6.8.0-147-generic`. Round-over-round deltas below are therefore
indicative, and the competitor arms are the control for how much of a
delta belongs to the host.

Baselines unchanged: `hotcoco==1.0.1`, `faster-coco-eval==1.8.0`,
`pycocotools==2.0.11`, `boundary-iou-api@37d2558`, `panopticapi@7bb4655`,
`mmsegmentation@c685fe6`, `lvis-api@031ac21`.

## Headline — real RF-DETR predictions, COCO val2017, one CPU

| cell | vernier | hotcoco | faster-coco-eval | pycocotools |
| --- | ---: | ---: | ---: | ---: |
| bbox, Nano (513,808 dets) | **954.6 ms** | 2.291 s (2.40×) | 5.438 s (5.70×) | 22.765 s (23.85×) |
| bbox, Seg-Nano (430,516 dets) | **1.288 s** | 2.590 s (2.01×) | 5.436 s (4.22×) | 21.506 s (16.70×) |
| segm, Seg-Nano | **2.343 s** | 4.863 s (2.08×) | 9.967 s (4.25×) | 22.271 s (9.50×) |

Previous round (2026-09 RF-DETR snapshot): Nano bbox 993 ms, Seg-Nano
segm 2.38 s. hotcoco is flat on both, and vernier is 3.9 % and 1.6 %
faster.

Peak RSS on Nano bbox: 390 MiB, against 997 MiB (hotcoco), 1384 MiB
(faster-coco-eval) and 1429 MiB (pycocotools).

**hotcoco's evaluate kernel still wins one cell.** On Seg-Nano bbox, its
`evaluate` stage takes 0.638 s against vernier's 0.929 s. vernier is
still 2.0× faster end to end, because hotcoco's `load` stage takes 1.474 s
against vernier's 0.124 s. On Nano bbox the order flips, with vernier at
0.632 s and hotcoco at 0.718 s. The stage splits are not strictly comparable
across impls, because vernier parses JSON inside `evaluate`. That makes the
Seg-Nano result a conservative statement of hotcoco's lead.

vernier moved −1.6 % (bbox), −2.3 % (segm), −1.0 % (boundary) and

rise in the pycocotools ratio (18.74× → 22.41× on bbox) comes from the
reference getting slower on the updated host, not from vernier. The
README headline uses the real-prediction rows, where pycocotools moved
only +2.4 %.

| cell | vernier | oracle | ratio |

LVIS is the largest vernier move among the release-mode cells: 2.498 s →
2.318 s (−7.2 %), with hotcoco_lvis flat (−0.2 %). That is the shape
0.5.5's seeded CSR annotation/detection indexes and image-order cache target:
many categories, many images, and lookups that dominated before. Peak RSS
fell from 1.11 GiB to 1.02 GiB.

**LVIS parity is unchanged.** vernier is bit-equal to `lvis-api` (tensor
hash `5d0a5013f3ec`, same as 0.4.0). The float-tolerance tier against
`hotcoco_lvis` fails at 7,069 positions, with the first divergence at
8.0e-3. That is the known-open hotcoco LVIS divergence. Every other cell's
parity tiers passed.

## Cells whose gate failed

Reported rather than re-rolled, as in 0.4.0:

* `hotcoco` on COCO bbox: 5.10 % at one CPU in the headline run and
  6.44 % on the `nt=1` thread cell. It also failed in all three 0.4.0
  runs of this cell while the other impls passed, so the variance is its
  own.
* `pycocotools` on COCO segm: 11.85 %. Its bbox cell moved +17.5 % with
  a tight 1.12 % IQR, so the reference really is slower on this host. The
  wide segm IQR adds noise on top of that shift, so treat the segm ratio
  as approximate.
* vernier keypoints at `nt=8`: 5.25 %.
